# 寻微 · 智能搜索工作台

一个在本机运行的多平台公开信息搜索程序。自然语言输入 → AI 拆解关键词和条件 → 多来源检索 → 核对证据 → 根据实际线索调整方向 → 带来源的 AI 总结。支持随时停止、保留结果和继续深挖。

也支持 **GitHub Pages 网页 + 独立搜索服务**。Pages 负责界面，Python 服务负责实际搜索、AI 总结、每轮进展和数据保存。部署方法见 [GitHub Pages 部署说明](PAGES.md)。网页中的「连接搜索服务」可填写 HTTPS 服务地址及专用访问令牌；AI 服务密钥仍由搜索服务保存。

公开访客服务支持两种模型方式：**使用站主 API**，或**自己配置 API**。每个访客有独立的临时会话、模型设置、搜索记录与资料。站主密钥只通过服务器环境变量提供，访客无法查看或修改。Render 托管方式见 [后端上线说明](HOSTING.md)。

## 启动

需要 Python 3.10 或更高版本，无需安装第三方 Python 包。

Windows 双击 `start.bat`，或在本目录执行：

```powershell
python run.py
```

浏览器会打开 **http://127.0.0.1:8877**。关闭启动窗口或按 Ctrl+C 停止服务。端口冲突时执行 `python run.py --port 8878`。

macOS / Linux 可执行 `python3 run.py`。

## AI 设置

左下角「搜索与模型设置」中填写地址、模型和 API Key，再点击「保存并测试连接」。默认地址与模型为：

- API 地址：`https://api.a6api.com/v1`
- 模型：`deepseek-v4.1-flash`
- 接口格式：兼容 Chat Completions，调用 `/chat/completions`。

当前机器可使用程序目录外随附的「启动寻微.bat」，它会读取工作区 `work/xunwei-data` 中已配置的测试密钥。**分发 ZIP 不包含密钥、搜索历史或本地资料**。从 ZIP 解压后的新副本需自行填写密钥。

默认密钥保存在 `.local/settings.json`；通过 `--data-dir` 启动时保存在指定目录的 `settings.json`。密钥不会返回浏览器或写入搜索历史。设置中密钥留空表示保留，清除需要勾选对应选项。本地配置文件为明文，请勿分享或提交数据目录。

也可设置环境变量 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`、`TAVILY_API_KEY`、`BRAVE_API_KEY`、`SEARXNG_URL`，它们在启动时覆盖文件配置。通过 `XUNWEI_DATA_DIR` 或 `--data-dir` 可指定数据目录。

**开启 AI 后，问题及选中的网页片段、相关导入原文会发送给你配置的 AI 服务。** 关闭「AI 理解」可仅做关键词搜索。第三方 API 的费用和数据处理规则由服务提供者决定。

## 搜索范围与实际边界

| 来源 | 程序能自动检索的内容 | 限制 |
| --- | --- | --- |
| B 站 | 无登录可访问的公开视频搜索，包含平台返回的播放数 | 不覆盖全部动态、评论、专栏；接口可能限流 |
| 小红书 | 网页搜索引擎已收录且能返回的公开链接 | 没有接入小红书内部搜索授权；未收录笔记可能没有候选 |
| 知乎 | 网页搜索引擎已收录的公开问题、回答等链接 | 无法保证登录后内容或全文可读 |
| 微信公众号 | 搜索引擎已收录的 `mp.weixin.qq.com` 公开文章 | 提供搜狗微信人工搜索入口；没有微信内部全文搜索授权 |
| 美团、大众点评 | 搜索引擎已收录的公开商户、评价等网页链接 | 未接入平台内部数据库；可能需要登录或只能看到摘要 |
| 抖音、贴吧、豆瓣 | 搜索引擎已收录的公开页面，并提供对应浏览器搜索入口 | 动态页面、验证码及未收录内容可能无法取得 |
| GitHub | 匿名公开 API 检索 issue、PR、仓库描述；深入档按预算读取 issue 的公开评论 | 不含私有内容、授权代码搜索或未取得的评论；匿名限额与访问间隔会影响耗时 |
| Stack Overflow | StackExchange API 检索公开问题及正文、实际浏览量；深入档读取按票数排序的公开回答 | 回答读取有条数上限；遵守 backoff 和每日配额，不包含未取得的评论 |
| V2EX、CSDN、博客园、Reddit | 搜索引擎已收录的公开页面和浏览器入口 | 未接入这些平台的内部数据库；可能只有摘要 |
| 自定义网站 | 按指定域名检索公开索引；或读取公开站内搜索模板返回的结果链接 | 最多 6 个网站；模板仅适合公开 HTML 搜索，不包含登录会话或 JavaScript 执行 |
| 公开网页 | Bing RSS、DuckDuckGo HTML，以及可选搜索 API | 网络和上游规则变化会影响可用性与相关性 |
| 本地资料库 | 你主动导入的原文，通过中文关键词、AI 扩展一起检索 | 不自动获取登录会话；导入内容的真实性仍需核实 |

**无法承诺搜到所有“只有几个人看过”的帖子。** AI 负责扩展检索和检查证据，本身不会获得平台未开放的数据。访问量不公开时显示「未知」；“已知 ≤100”只筛选来源实际返回的数字。B 站的数字是视频播放数，不等同于独立观看人数。

遇到需要登录、验证码、robots 禁止或访问拒绝时，程序保留摘要并标注原因，不绕过限制。每轮搜索都提供站内搜索链接，可在自己的浏览器里进一步查找，并将有权使用的原文导入本地资料库。

若需要稳定、更广的网页召回，在设置中配置 Tavily、Brave Search 或公开部署且启用 JSON 输出的 SearXNG。它们同样不能保证覆盖未收录帖子。SearXNG 连接器目前只接受公网、标准端口的实例。

## 如何使用

1. 输入具体问题，例如「中科大中区桃李苑哪道菜好吃」。名称、地点、时间和条件越具体，越容易核实。
2. 选择平台，也可展开「指定网站 / 站内搜索」添加网站；在「每轮深度」选择快速、深入或穷尽线索。深入档会扩大检索和公开正文、回复读取预算。
3. 保持「AI 递进搜索」开启，选择每次 3、6、12 轮后暂停，或「直到手动停止」。查看右侧逐轮记录、检索词、调整原因和来源情况。
4. 优先查看匹配充分或部分匹配结果，展开逐条证据并打开原文。
5. 需要保存未收录内容时，在「本地资料库」导入标题、链接和正文。
6. 点击「停止搜索」立即保留当前结果；点击「继续深挖」沿已有线索搜索。可导出 JSON，或在「搜索记录」回看最近 100 次保存的搜索。

## 递进搜索与人工控制

首轮优先覆盖所选平台和网站；范围超过单轮预算时，下一轮先探索尚未检索的范围。后续轮次将实际找到的相关片段、已查过的关键词、各平台命中情况和未满足条件交给 AI，生成新的检索表达；出现有效线索的平台获得更多检索任务。模型可以使用别名、拆分问题或追查具体地点，但结果核验始终使用原问题与原始条件。没有证据的推测不会变成已核实的答案。

递进模式的三档预算如下，深度与轮数独立；「穷尽线索」仍有单轮上限，不表示搜索了所有网络内容。

| 每轮深度 | 逻辑来源检索任务上限 | 正文或回复读取上限 | 新候选核验上限 |
| --- | ---: | ---: | ---: |
| 快速 | 20 | 3 | 16 |
| 深入 | 32 | 6 | 24 |
| 穷尽线索 | 48 | 10 | 24 |

最多 4 个检索任务并发；每个任务的直接 API 分页也有上限，以上任务数不等于实际 HTTP 请求数或帖子数。AI 条件较多时，实际核验条数可能低于表中上限。最多展示 240 条候选；同一范围内已完成的检索词和重复链接会去重，同一来源补充正文后重新核验。关闭「AI 理解」后，新搜索采用普通单轮检索，不进行模型规划、核验和自动总结；已保存搜索仍可继续深挖。

程序优先独立检索精确版本串与稀有实体，过滤宽泛词条、同校非饮食内容和有逐字反证的候选。连续失败的来源会暂停本段后续请求，将预算留给可用来源；继续时重新尝试。GitHub 故障问题优先 issue 搜索，后续 AI 规划能看到已读取回复与当前总结，减少追查已取得的信息。公开回复按链接去重，失败或取消后仍可重试。

有限轮数结束后进入「等待你决定」；可继续追加轮数。选择「直到手动停止」时不设轮数上限；若来源全部失败、连续两轮没有新增结果或已无可用新方向，会暂停等待操作，避免重复消耗。AI 不会仅因自认为答案充分而结束搜索。

停止后不再安排新请求，已找到的结果、轮次和上一版总结保留；**已经发给外部服务的请求可能仍在服务端完成和计费**，其晚到响应不会覆盖已停止的结果。继续搜索会跳过已完成的请求，未完成请求可以重试；可修改深度后点击继续。每轮进展存入历史，重启程序后可继续已保存的线索。

## 指定网站及站内搜索

展开搜索框内的「指定网站 / 站内搜索」，填写名称与域名。只填域名时使用公开网页索引；也可填写该网站提供的公开搜索地址，将搜索词替换为 `{query}`，例如：

```text
名称：Python 官方网站
域名：www.python.org
搜索模板：https://www.python.org/search/?q={query}
```

模板必须是同域名的 HTTPS 地址，只能包含一个 `{query}`。程序读取 HTML 中的搜索结果链接，并只保留指定域名及其子域名的链接。指定 GitHub 等已接直接来源的域名且未填模板时，递进模式优先对应公开 API。若站点仅通过 JavaScript 加载结果、要求登录或阻止抓取，界面会说明原因，可用浏览器入口继续查询。可取消所有平台，仅搜索指定网站。「保存网站列表」会将配置保存在本机，当前未保存的列表也可用于本次搜索。

## AI 总结

开启「AI 理解」时，新搜索会自动生成总结，显示在结果列表上方。针对餐馆问题，会优先归纳来源明确提到的店名、菜品和推荐理由，不补写没有依据的信息。

已完成、暂停或已停止的搜索记录也可点击 **「生成 AI 总结」**，直接使用当时保存的结果，不重新检索。可「重新总结」或在失败后重试；原来的结果和筛选会保留。未开启自动 AI 的搜索，也能在配置好密钥后手动总结。递进搜索每轮获得新证据后更新总结；若更新失败或中途停止，会保留上一版并标注新增结果尚未纳入。

每条要点提供编号来源链接，可展开查看准确引用的原文片段，并区分网页正文、搜索摘要和本地导入。模型不能自行生成来源网址；没有有效引用的要点不会显示。总结会与历史记录一起保存，也会包含在导出的 JSON 中。

总结最多选取排序靠前的 16 条可用来源，一般来源每条最多 2200 字；含实际 API 回复的来源最多 14000 字，保留后续不同方案与回复者归属，总计不超过 35000 字。界面会说明实际参考和引用数量。它归纳已有材料，不保证覆盖全部结果或网页全文，也不把帖子的主观口味评价视为客观共识。引用存在不保证复合结论全部被引文支持，复杂配置仍应打开原文核对。没有可用结果时不会发起总结请求。

“已读原文”筛选表示成功提取了正文或来自本地导入，不代表独立事实核查。原文片段存在也不保证 AI 对含义的理解正确，应以原帖上下文为准。导入文本和公开网页使用不同来源标记。

## 每轮 AI 进展报告

开启「AI 理解」后，每一轮完成检索、核验和总结，都会生成一份进展报告；普通单轮搜索也支持。即使本轮没有新增结果或来源请求全部失败，AI 仍可依据实际过程说明障碍。关闭 AI 时仅显示程序统计，不生成推断或成功可能性判断。

- **搜索进展**：AI 依据本轮真实请求、返回情况及上一轮报告作简短评述。新增线索、补充证据、累计线索、请求数和失败数由程序直接统计。
- **目前可推断的信息**：分别展示「来源支持」与「待验证推断」。每项附可核对的来源和原文；缺少有效引用的内容不展示。推断会明确标注待验证，历史材料也不会被标作本轮新发现。
- **成功可能性**：按「高／中／低／信息不足」给出定性判断，解释理由、目前障碍和下一步建议。这里的成功指在原问题和已选范围内取得可核对的有效证据；它是 AI 对当前可见材料的判断，不是经过统计校准的概率或保证。

最新报告显示在结果上方，每轮「递进搜索记录」内可展开回看当时的报告；历史和 JSON 导出也会保留它。继续搜索时保留上一份报告，待新报告生成后更新。报告生成中仍可停止；停止后不会采用晚到回复，已保存的报告与结果保留。报告失败不会阻断后续检索，也不会伪装成 AI 已完成评估。

每轮进展报告额外调用一次 AI，最多使用 12 条来源、每条最多 1800 字；模型同时接收实际检索统计、原问题条件和前轮报告概况。旧版历史不会自动补发 AI 请求；从旧记录「继续深挖」后，新完成的轮次会生成报告。成功可能性的高低不控制搜索是否结束，仍由轮数设置和你的停止、继续操作决定。

## 普通单轮检索

取消「AI 递进搜索」后使用单轮流程：

- 快速模式通常选择最多 6 个“关键词 × 平台”组合，平台超过 6 个时扩大预算以覆盖所选平台；深度模式最多 12 个。每个组合交给所选搜索引擎并行查询；指定网站会另加检索任务。
- B 站快速模式使用综合排序；深度模式结合综合排序和最新发布分页，增加非热门内容进入候选的机会。受限时停止请求并报告。
- URL 去重并移除常见追踪参数；仅保留有关键词重合的候选，最多 60 条。
- 按需读取前 6 / 12 条公开网页正文；最多对前 24 条进行 AI 审查，其余明确保留为未核实。
- 关键条件必须有可见原文支持。程序逐字校验模型引用，模型编造的引用不会获得“支持”标记。匹配分用于排序，不是正确概率。
- AI 超时、响应异常或密钥缺失时保留关键词检索结果，并明确提示降级。

普通单轮搜索最多四次 AI 请求：检索规划、证据审查、结果总结和进展报告。递进搜索通常每轮最多四次 AI 请求：方向规划、新候选审查、总结和进展报告；没有候选时跳过审查和总结，仍可评估检索进展与障碍。手动生成或重新总结额外调用一次 AI，不重复搜索。网络请求均有超时与响应大小上限。轮数和平台越多，耗时和第三方调用费用可能越高。结果不会补成生成的帖子。

## 公开征友帖

程序仅支持成年人本人主动公开发布的征友帖子内容检索。年龄、学校、地区需要帖子明确自述；无法核实成年或本人发布时不展示对象候选。不会跨平台关联私人身份、查找小号或推断、筛选个人财务画像。

对于「07-10年的……相亲贴」，需要先说明是出生年份、入学年份还是其他时间。如果指 2007–2010 年出生，范围在 2026 年包含未成年人，不能用于相亲对象筛选。“家境 A8 以上”这类个人财务筛选也不支持。可改为明确成年、本人自发、公开内容的非敏感条件检索。

## 安全与维护

服务只监听 `127.0.0.1`，检查请求 Host 与 Origin。网页抓取校验公网 IP 并固定解析地址，拒绝内网、凭据 URL 和危险重定向；带 API 凭据的请求不跟随重定向。网页内容按纯文本显示。

业务数据默认位于 `.local`，也可位于你指定的 `--data-dir` 目录。当前配置好的本机实例使用工作区 `work/xunwei-data`。备份时可复制数据目录；分享程序时请排除它。没有设置遥测、云同步或自动上传资料库。

验证：

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

Node.js 仅用于可选的 JS 语法检查，运行程序不需要 Node.js。

代码结构：`search_app/server.py` 本地 API；`engine.py` 单轮检索与证据核验；`adaptive.py` 多轮调度与平台权重；`providers.py` 来源连接与正文提取；`ai.py` AI 兼容接口；`summarizer.py` 带来源的结果总结；`progress_report.py` 每轮进展、证据推断与定性成功评估；`storage.py` SQLite；`safety.py` 查询边界；`web/` 无构建前端。

API 调用格式参考：[Chat Completions 官方接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。第三方网关和模型是否支持某字段，以实际响应为准。
